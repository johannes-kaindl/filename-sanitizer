# GUI smoke checklist (maintainer material)

Runs with `npm run smoke:gui -- --port <port>` against a second Obsidian instance with its own profile (recipe in the header of `scripts/gui-smoke.ts`). The fixture vault is `fixtures/vault/` and is rebuilt by `npm run smoke:gui -- --setup`. The driver itself is the foreign writer: it creates files with the file system, not through Obsidian's API. Quiet time is set to 1000 ms for the run.

`--abschnitt s7` runs only point 0, O, S7, J and M (the long measurement with 17,000 files and the 245 cards, no settings window): the subset is the target of that run, so it is meant for repeating the slow measurement on a fresh process each time.

## Check points

| # | What is measured | How |
|---|---|---|
| 0 | Plugin loaded, restricted mode of a fresh profile lifted | `app.plugins.plugins["filename-sanitizer"]` exists |
| O | Device value: switching *This device repairs* off keeps it off (Obsidian's local storage drops a stored `false`, so the value is stored as text); the stored raw value is printed | `device.setRepairs(false)` and `device.repairs` read in the renderer, raw value read with `app.loadLocalStorage`, reset afterwards |
| A | First start: an existing name (`alt: bestand.md`) stays untouched and is listed with reason *legacy* | device values reset, plugin enabled, file and `engine.pending()` read |
| B | `c1: rest.md` created from outside stays for 300 ms, then becomes `c1 — rest.md`; the link in `Links.md` follows and the old name is an alias; the control file `kontrolle.md` stays; `c2: fremd.foo` (any extension) is repaired the same way | files read from disk |
| C | `Ausnahme/x: y.md` stays (exception), `Draussen/x: y.md` is repaired | exception pattern `Ausnahme/` |
| R | Rule change: `r~alt.md` is valid, then `~` becomes an extra character; the name stays and the review list names it with reason *legacy*; `r2~neu.md` created afterwards becomes `r2-neu.md` | settings saved through the plugin, files read from disk, `engine.pending()` |
| D | `alwaysUpdateLinks` off: no "Update links" dialog, the file stays, the review list names the reason; after switching it on, the list renames and the link in `Links2.md` follows | `app.vault.setConfig` |
| E | Three repairs in a row give one notice ("Renamed 3 files …") | notice text read after a quiet period |
| F | The log file holds the line of `c1: rest.md` (event, schema 1), every line parses, the control file has none | `.jsonl` read from disk |
| G | `api.sanitizeName` answers synchronously, `checkName` too, an empty caller gives `invalid-input` | called in the renderer |
| L | A real *Update links* dialog (link setting off in Obsidian, the plugin's own decision forced to "on") stays open past the 10-second limit: the engine halts and logs *failed*; after confirming the dialog the file is renamed, the log gets a *repaired* line saying it was confirmed after the deadline, the reserved target path is released, the engine stays halted | dialog opened by the plugin's own rename, `engine.halted` and `engine.ownTargets` read, log read with `logStore.read` |
| H | In *Review first*, unticking `h2: x.md` and pressing *Rename ticked* renames `h1: x.md` only; the card of `h2` says "Stays as it is"; the log holds *confirmed* and *repaired* for `h1` and *skipped* for `h2` | clicks on the cards and the button, log read with `logStore.read` |
| I | Settings: help row first, groups Repair, Exceptions, Replacements, Log, Advanced in that order, three collapsed | settings window read |
| K | Settings at 390 px (sidebars collapsed, measured inside a 390 px simulation of the settings window), as shipped and with every group unfolded: no horizontal overflow, every row's right edge inside 390 px, more rows after unfolding, no fold left closed; the detail also reports the column width, the smallest control and how many setting names are cut off (information, not a limit) | DOM measures in the settings window, screenshots `settings-390.png` and `settings-390-offen.png` under `--shots <folder>` read by the maintainer; a desktop window of 390 px keeps the two-pane settings layout and is not a phone, the device is measured separately |
| N | Settings: after a reset button in the replacements group (which redraws the tab) and after closing and reopening the settings, the groups opened before are still open | DOM read in the settings window; the groups are folded again at the end |
| S7 | Duration of the start scan with 17,000 valid and 245 invalid names (measurement, no limit) | `engine.scanNow()` timed three times; valid only when the index holds all files and the file count stayed equal over two readings; the wait ends when the count has not moved for 120 s (cap 30 minutes), not after a fixed time |
| J | The view at 390 px (sidebars collapsed): 245 cards, no horizontal overflow, right edge inside the window, smallest button at least 28 px | DOM measures, screenshot `--shots <folder>` read by the maintainer |
| M | In the review list with 245 cards, scrolled to 40 %, focus on the *Reject* button of one card, click: the list is redrawn (the time until the card is rebuilt is reported, sampled every 10 ms), the scroll position is unchanged (±2 px) and the focus is on the same button of the same card | DOM measures, screenshot `review-390-nach-ablehnen.png` under `--shots <folder>` |

Every point carries its own control: L the same rename in the same run before the dialog is confirmed (nothing in the log yet), M the card index and the scroll position read before the click, N the count of closed groups before the reset, B the valid control file, C the same name outside the exception, D the switch turned back on, F the control file in the log, H the ticked sibling.

## Counter-probe

A local mutation (not committed) makes `hasFinding` in `src/obsidian/engine.ts` always return `false`; the run must turn red at B, C, D, E, F, H and S7 (no finding, so no review list) and stay green at 0, A, G, I, K and J (the start scan does not use `hasFinding`).
